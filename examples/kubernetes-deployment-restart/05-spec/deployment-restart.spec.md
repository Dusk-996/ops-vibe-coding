# Deployment Restart Spec

> 教学行为契约；仓库没有此 API 或数据库实现。所有验收条款均为待真实项目验证的要求。

输入：[产品范围](../01-prototype/approval.md)、[Mock](../02-react-mock/contract.md)、[Architecture Final](../04-architecture/stack-selection.md)。

## 功能与授权

可信 SSO 身份在后端通过 Namespace 授权后，可明确确认一个 Deployment 的重启请求。浏览器按钮不替代授权。读取操作记录同样受范围约束，错误不得泄露凭证、堆栈或未授权操作详情。

身份/授权拒绝不调用 Kubernetes；审计可用时保存拒绝事件，审计不可用则明确记录脱敏日志/告警降级，不能承诺不可用数据库中仍有完整审计。

## API 与结果

- `POST /api/deployments/{namespace}/{name}/restart`，请求头 `X-Operation-ID`，显式目标确认。
- `GET /api/audit?operation_id={id}`；既有 resource/namespace/name 查询保留。参数只是筛选，不扩大读取权限；查询保存记录，不自动核验集群。
- 200：Kubernetes 明确接受，最终状态与审计持久化已确认，界面为“请求已提交”。不代表 rollout 完成。
- 401/403：身份/授权失败；404：目标未找到或无可见性；409：ID 绑定冲突或同目标仍有活动/未知提交。
- 504：API 超时，提交结果未知，禁止自动重试。审计或事务确认故障用 503，明确是否已调用 API；不能仅按 HTTP 状态决定安全重发。

响应/记录分别表达操作 ID、当前可确认的持久状态、远端观测（not_sent/accepted/rejected/unknown）、最终审计是否确认。无法确认落库状态时写未确认，不捏造持久状态；即使已观测 accepted，也不得在审计未确认时显示普通成功。

## 状态及持久化

| 持久状态 | 定义 | 同 ID 能否再次发送 |
|---|---|---|
| SUBMITTING | 意图和占用已持久化；可能尚未发出或已经发出 PATCH | 否 |
| SUBMITTED | API 明确接受，最终状态和审计已确认 | 否，只返回记录 |
| REJECTED | 有明确证据证明本次未形成变更，结果已持久化 | 否，只返回记录 |
| UNKNOWN | 无法证明提交结果，需要核验 | 否 |

正常迁移为 SUBMITTING → SUBMITTED/REJECTED/UNKNOWN。Unknown 只能经核验变为最终状态；若最终写入未确认，库内可能仍为 SUBMITTING。不要把“等待时间长”当作失败或原进程已终止的证据。

UI Idle/Confirmation/Running 为交互状态；Running 不授权重发。用户结果为 Submitted、Rejected、Unknown 或审计未确认提示，不能把旧 Success 解释成工作负载已恢复。

## 幂等、占用与调用顺序

1. 后端检查当前身份和授权，将操作 ID 绑定可信身份、服务端集群引用、Namespace、Deployment 名及规范化请求指纹。
2. 相同 ID 与绑定返回原结果或待核验记录；不同绑定拒绝，不泄露原记录。未知/活动的同目标占用拒绝新 ID。
3. 在同一数据库事务中保存意图和目标占用键 `cluster_ref + namespace + deployment_name`。事务确认前禁止 PATCH。
4. 本同步请求在所有调用层发送至多一次 mutation；关闭客户端隐含自动重试。可在同一 PATCH 的模板注解中保存操作标识，辅助管理员取得正向关联证据，不增加自动读取权限。
5. 明确 accepted/rejected 后，同一事务保存最终状态、审计并释放占用；超时或不确定结果保存 UNKNOWN 并保留占用。
6. 若最终事务未确认，不再发起 mutation，保留核验路径。完成 ID 不改绑、不因刷新重发；本示例不做记录过期/清理。
7. 提交占用释放不代表 rollout 已完成。新的独立人工操作仍需新 ID、重新授权和确认；本例不保护整个 rollout 周期。

## 审计

保存操作 ID、可信操作者、目标、请求/结果时间（未知则注明）、请求指纹、阶段、远端观测、最终状态及脱敏失败类别。意图、最终结果、核验更正可关联；原始事件不可静默覆盖。凭证、SSO token、Secret 值不进入记录或用户错误。

## 失败决策

| 情景 | 要求 |
|---|---|
| 用户取消 | 不请求 API，不 mutation |
| 意图库不可用或事务未确认 | 不调用 Kubernetes；明确 not_sent 和记录限制 |
| API 明确拒绝且可证明未变更 | 结果持久化后 REJECTED；不能将不确定5xx归为确定拒绝 |
| 超时/连接中断 | UNKNOWN，保留占用，不自动重试 |
| API 已接受但最终审计写失败 | 分别说明 accepted 与审计未确认，库内状态不得臆造，保留占用 |
| 原进程在持久意图后崩溃 | 不恢复发送；原记录保留，确认原处理已结束后人工核验 |
| 同目标新 ID／同 ID 重放 | 分别按占用冲突／已有结果处理，不产生第二次 mutation |

## 人工核验与受控维护

1. 现有管理员以已有权限只读取证，关联操作 ID、目标、请求及集群审计/已接受响应/操作标记等权威证据。单纯“未看到标记”不能证明从未提交。
2. 只有确认原处理已结束，且证据能证明已接受或未变更时才提出结果更正；否则维持未知和占用。
3. 有权人员批准具体操作 ID、目标、证据及更正范围；未经批准不提供强制解锁。
4. 有权维护者检查当前记录版本与原状态，在同一事务中更正为 SUBMITTED 或 REJECTED、追加核验事件并释放占用。记录核验人、批准人、维护人、依据和时间；并发更正或事务未确认继续阻断。
5. 本轮只定义维护契约，不提供可执行 SQL 或平台恢复接口。采用项目须提供已审查的实际维护规程与验证，不能直接在生产库照本例操作。

## 验收条件与测试边界

- 可信身份、范围授权、确认与取消均验证；拒绝路径不得调用 Kubernetes。
- 意图及占用持久化先于单次 PATCH；不同 ID 同目标并发、相同 ID 重放/改绑不重复执行。
- Submitted 仅证明提交且最终审计确认；超时为 Unknown，不自动重试。
- 意图/最终事务故障、进程中断、已接受但审计未确认均不导致盲目解锁或重发。
- 授权查询能按操作 ID 找记录，不能跨范围泄漏。
- 人工更正的权限、证据、版本条件、事务及失败阻断有实际验证。
- 原始测试关联固定代码/配置/环境、命令、时间、退出码及输出；替身测试不能证明真实 RBAC 或恢复有效。

测试 seam：可替换授权评估、可计数的 Kubernetes client、支持事务/故障/冲突的操作审计仓储、前端状态 Mock。真正开发前由人确认 seam 与范围。

批量、回滚、定时、自动重试、HA、Worker、自动核验及清理不属于 v0.1。真实部署的留存、增长、备份与发布需要另行批准。
