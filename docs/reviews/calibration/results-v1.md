## 逐项复核依据与修改建议

- **D1**。C1 对应 R1 的单目标、本地范围。C2 有一处分差，第一位认为“需要在多个窗口核对”缺现状来源，第二位把文档自身当作现状依据。C3 能从 U1 和下一步找到原型作者及范围。A 交代了谁在何种流程遇到什么问题。B 的“改善体验”无法核验。建议作者补上访谈或操作记录，将成功标准写成“在本地样本上，使用者能说清取消后是否提交、被接受是否意味着 rollout 已完成”。这是修订建议，材料 D1 尚未改变。
- **D2**。摘要没有指回 R2 的候选方案和只提风险的范围（C1），没有引用 2/3 的样本（C2），也没有可执行的下一步或结束理由（C3）。无法还原使用者及判断场景（A），“系统存在风险”缺触发条件和影响（B）。建议评估人明确“一次采样无法证明卡住”，解释误报会如何影响值班判断、还需何种时间趋势，并写清到此结束的决定或待确认人。
- **D3**。P3 和 R3 定位范围（C1、A），E3 确实支持计数 1 和退出 1，报告如实转录了这两项观测（C2）；T3 与复验路径可定位（C3）。结果表把这个失败报为 PASS，命中 B 的 0 分及封顶条件。建议修正 C1 结果表并保留 E3。修订报告无需将产品失败改为通过。
- **D4**。同一 P3、R3、E3 和 C1 分别支持范围、观测与执行边界（C1、C2、A）。T3 给出了修复与复验行动（C3），期望 0、实际 1、退出 1 与 FAIL 完全对应（B）。没有产物扣分项；产品是否修复须看后续实现与新的执行证据。
- **D5**。R5 与 U5 支持已选定的本地 Mock 和单目标范围（C1、C2），原型作者可据文档绘制目标确认框和已提交提示（C3）。A 缺当前做法及具体困难，B 缺验证样本。建议补“谁在何处核对结果”的访谈，选择一个可重放的提交回执，让同事从界面判断请求状态。

两次评审的五个合格结论一致。D1 的 C2 分差促使我们明确举证口径：产物原文可以证明作者作出的设计选择；声称“用户目前如何操作”需要访谈、样本等来源，或明确写成待验证假设。该口径写入规则 1.0，保留两位复核者的原始分。重用时请固定题面版本；若修改规则版本，另列基线。
