# Design: 智能服务器巡检与定时邮件推送平台（ops-inspect-demo）

- **日期**：2026-11-23（Rev 3：P2 反向校准，严格区分“静态目标/IP 登记导入”与“系统主动检测采集指标”）
- **模式**：`mutating`（含目标资产写入、批量导入、主动巡检触发、定时配置与外部邮件发送）
- **状态**：Design 已与原型/架构对齐 → 待验收新版原型与 P2 定稿

## Context

运维团队需要一个内部 Web 智能巡检平台：登记或批量导入目标服务器的静态信息与连接方式（主机名、IP/地址、种类、厂商、采集驱动与 SSH 凭据别名），由系统主动检测采集各服务器的真实总内存、可用剩余内存、CPU 核数与 CPU 使用率，并按每日固定时间自动先巡检再生成 Markdown 巡检报告推送至指定邮箱。

## Goals / Non-Goals

**Goals（可观察的成功标准）：**

- **G1 静态目标登记与主动巡检分离（非静态台账）**：
  - 登记/编辑仅维护目标静态信息：`host`、`address`（IP/域名）、`type`、`vendor`、`collectorType`（`ssh` / `local` / `mock`）、`sshPort` / `sshUser` / `sshCredentialRef`（仅凭据别名，严禁明文密码/私钥）。
  - 动态指标（总内存、可用剩余内存 `MemAvailable`、CPU 核数、CPU 使用率、健康状态、最后检测时间、失败原因）完全由采集引擎主动检测刷出，只读不可手改。
  - 页面 1（`#/servers`）支持单台 **`检测`** 与 **`立即全量巡检`**（5 并发隔离，单台超时/不可达不拖垮其他主机）。
- **G2 目标服务器 IP/连接信息批量导入导出**：
  - 导入：下载标准 CSV 模板，上传 `.csv` / `.json`（`host, address, type, vendor, collectorType, sshPort, sshUser, sshCredentialRef`），先校验预览再按策略（跳过/覆盖）批量落库，新导入目标初始状态为 `待检测`。
  - 导出：一键导出 CSV（UTF-8 BOM + 防公式注入）与 JSON，含静态连接信息及最新检测指标。
- **G3 每日定时巡检推送与邮箱双模式（页面 2 `#/schedule`）**：
  - 精致 4×6 小时 / 2×6 分钟网格弹层时间选择器，支持每日定时启停与多收件人校验；
  - 定时触发或手动“立即推送”支持确认预览，标准 SMTP（环境变量注入）与本地模拟收件箱双模式；推送防并发 `409`、SMTP 超时 `504` 且**不自动重试**；支持按需下载 `.md` 报告。
- **G4 认证鉴权与全量审计**：
  - `admin`（增删改、导入、巡检、改定时、推送）与 `viewer`（只读、导出）；未登录写操作 `401`，`viewer` 越权写操作 `403`，所有操作与异常均写审计。

**Non-Goals（明确不做）：**
- 不在目标机安装常驻 Agent，不接入外部 Prometheus/Zabbix；
- 不引入 Redis、MQ、独立 Worker 或微服务；
- 不在数据库、代码、日志或前端暴露明文 SSH 私钥、密码或 SMTP 授权码。

## UI 与视觉基线
- 风格 C（极简工程克制感）融合 Refactoring UI（正文/表格字号 ≥ 14px、轻分割线、双页 Hash 路由 `#/servers` & `#/schedule`、无页面常驻大块 Markdown 展开、自定义网格弹层时间选择器）。
