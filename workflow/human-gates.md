# 人工门禁、三段汇报与熔断协议（Ops Vibe Coding v3.4）

> **铁律**：阶段内机器自动修错闭环；阶段间强制停手交由人类确认拍板，**严禁 Agent 代签 `approve`**；**只有 P5 测试全过并获批后，才允许进入 P6 设计部署**。

## 1. 7 个人工硬锁点

`vibe_gate.py` 在 `.vibe/state.json` 中为全部 7 个阶段设置 `approved` 硬锁：
- 未获 `approve p1` → `check p2` 直接失败；
- 未获 `approve p2` → `check p3` 直接失败；
- 未获 `approve p3` → `check p4a` 直接失败；
- **未获 `approve p4a`（前端实机验收通过）→ `check p4b` 直接失败，严禁提前编写后端**；
- 未获 `approve p4b` → `check p5` 直接失败；
- **未获 `approve p5`（全面真环境测试通过）→ `check p6` 直接失败，且 P1–P5 任何提前编写的部署文件都会触发 `[EARLY-DEPLOY]` 阻断**；
- `approve p6` 落盘后项目进入 `RELEASED` 状态。

```bash
# 仅在用户明确回复“P<stage> 通过”后由人类或经人类明示后执行：
python ../ops-vibe-coding/scripts/vibe_gate.py approve <stage> --project . --by user --note "<验收结论>"
```

## 2. 阶段末固定三段汇报模板（面向运维工程师的大白话）

每个阶段 `check <stage>` 返回退出码 `0` 后，Agent 必须**立即停手**，按以下三段输出简洁汇报（禁止把整段源码直接甩给用户）：

1. **一、本阶段完成了什么 + 机器检查证据**
   - 简明列出本阶段关键产物（附文件路径）；
   - 给出 `vibe_gate.py check <stage>` 的真实退出码、构建/测试真实条数与耗时；
   - **如实单列未安装或跳过的检查项**（如 `ruff`/`bandit`/`gitleaks`/`hadolint` 未安装，绝不谎报通过）；
   - **P3 特例**：必须醒目说明“当前仅空应用骨架，尚无业务代码可启动，也未提前创建部署文件”。
2. **二、请你核对与验收的核心点**
   - P1：浏览器直接打开 `style-picker.html` 与 `index.html` 核对页面、字段与流程；
   - P2：用对照表确认前后端技术栈与核心采集/执行机制；
   - P3：目录骨架树 + 业务主流程大白话 + 验收用例清单；
   - P4a：给出本地可访问 URL，列出 4–5 个核心点验动作与 `04-parity-review.md` 核对结论；
   - P4b：给出联调 URL、测试账号、实测真采集/真发信核对项与双审查结论；
   - P5：呈现真环境（Linux/WSL）全量单测与多域端到端实测日志及报告；
   - P6：呈现选定的生产部署包、部署扫描结果、实机启动/探活/备份恢复/回滚日志及 `06-release-gate.json` 结论。
3. **三、下一步预告与等待确认**
   - 用一句话说明确认后下一阶段将做什么（P5 结束时额外列出可选的 P6 部署形态请用户拍板），等待用户回复确认或提出修改意见。

---

## 3. 自动打回与 3 轮熔断

- 阶段内遇到构建失败、单测失败、扫描告警或门禁不通过时，Agent 读取错误输出自主修复并重跑 `check <stage>`；
- `state.json` 自动记录 `retries` 计数；**同一阶段连续失败达 3 轮触发熔断（退出码 `2`）**，Agent 必须立刻停止盲目试错，把失败根因、已尝试方案与阻塞点如实上报人类决策。
