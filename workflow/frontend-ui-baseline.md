# 生产级运维前端 UI 与交互基线（Ops Vibe Coding v3.4）

> 本基线沉淀自真实端到端标杆案例 [examples/ops-inspect-platform/](../examples/ops-inspect-platform/)，适用于 **P1 原型设计** 与 **P4a 前端实现**。

## 1. 强制组件与布局红线（违者直接打回）

| 维度 | 禁止做法（Demo 感 / 廉价感） | 生产级标准做法 | 门禁校验 |
|---|---|---|---|
| **下拉选择器（#14）** | 裸用浏览器原生 `<select>`（系统刺眼蓝框、尖角边框、字距挤压）或超长滚动时间下拉 | 统一封装自定义圆角浮层组件（`CustomSelect`：柔和边框、微投影、浅灰悬停、右侧勾选 `✓`、`Esc` 关闭）；时间选择用 4×6 小时 / 2×6 分钟网格弹层 | `check p4a` 自动扫描阻断 `<select` |
| **报告与邮件预览（#15 / #20）** | 用 `<pre>` 直接把 `#`、`##`、`|---|` 等原始 Markdown 源码吐给用户看；或将全部正常主机铺满长表 | 底层继续存/导 `.md`，页面预览与确认弹窗用纯 React 排版组件（`ReportView`，禁用 `dangerouslySetInnerHTML` 防 XSS）；报告采用 **总览 + 仅详展异常主机 + 正常省略明细** 结构 | 人工验收 P4a/P4b |
| **历史记录 / 审计日志（#16）** | 手风琴点击折叠卡片（展开后列表跳动、后续记录被顶飞） | **单行高密度表格 + 点击右侧滑出详情抽屉（Drawer）**，邮件发送记录与全量操作审计保持 100% 一致交互，支持 `Esc` 关闭与导出/复制追踪号 | 人工验收 P4a |
| **操作反馈通知（#17）** | 占满页面顶部的文档流横条、永不消失、正文充斥 `[200 OK · op-xxx]` / `INSPECT_ALL` | **右上角悬浮卡片 + 10 秒自动隐藏（鼠标悬停暂停倒计时）** + 底部细进度条；正文用运维人话讲结论、点名异常主机与建议动作；追踪号放右下角极淡灰角标 | 人工验收 P4a |
| **文案与模拟边界（#17）** | 下拉框出现“测试模拟/测试替身”等开发词；模拟推送却写“已送达收件箱”误导发了真邮件 | 全站统一生产业务术语（`SSH 远程采集` / `本机采集` / `模拟探针`）；模拟通道显式声明“仅写入本地模拟收件箱，未发送真实外部邮件” | 人工验收 P4a |
| **信息架构克制原则（#21）** | 顶栏堆砌导入/导出/新增按钮；导出 CSV 和 JSON 拆成两个重复按钮；页面挂“说明书式”冗长副标题；导航标签带多余数字胶囊；登录页写“口令”、登录后显示 `admin (admin)`；未登录直接渲染空表格或退出残留内网资产 | 页面标题栏保持纯净；列表主操作（`立即全量巡检`）放列表板块头部，**`批量导入`、合并后的 `导出 ▾` 下拉菜单、`+ 添加服务器` 归位至筛选行同一板块右侧**；删掉解释性副标题与导航冗余数字胶囊；登录用标准 **`账号` / `密码`**，未登录展示极简门面引导，登录后仅显示用户名，退出或 `401` 立即清空敏感内存态 | 人工验收 P4a/P4b |
| **视觉与排版底线（#6）** | 12px 挤小字、纯白死板分割线、单页无限纵向堆叠多模块 | Refactoring UI 原则：正文/表格 `≥ 14px`、等宽数字对齐（`tabular-nums`）、轻边框加微投影层级、多核心模块拆分为独立 Hash/Router 页面 | P1 风格对比 + P4a 验收 |

## 2. P4a 无后端验收双态模式（#18，零返工对接 P4b）

```js
// src/api/client.js 核心约定
// 1. 生产构建（.env.production: VITE_USE_MOCK=false）永远直连真实 /api/*，严禁回退 Mock。
// 2. 仅在开发态 (import.meta.env.DEV) 启动时探测 GET /health（1.5s 超时）：
//    - 探测失败（P4a 后端尚未编写）-> 自动启用 localPreviewAdapter 并显示顶部验收横幅；
//    - 探测成功（P4b 后端已上线）  -> 自动直连真实后端 API 与 Bearer 登录，前端零改动。
export function isPreviewFallbackMode() {
  return import.meta.env.DEV && !backendAvailable;
}
```

## 3. 运维人话反馈文案模板对照

| 操作场景 | 反面示例（禁止） | 正面模板（推荐） |
|---|---|---|
| 单台检测正常 | `[200 OK · op-a1b2] host1 检测完成: CPU 16%` | 标题：`实时状态已更新`；正文：`host1 运行正常，当前 CPU 16%，可用内存 10.0 / 32 GB。` |
| 单台高负载 | `[200 OK] host2 检测完成: CPU 86%` | 标题：`检测到主机负载偏高`（warn）；正文：`host2 当前 CPU 86%、可用内存 38 / 256 GB，建议及时排查进程占用。` |
| 全量巡检含异常 | `[200 OK] 成功 5，失败 1` | 标题：`全量巡检完成（发现需关注主机）`；正文：`共检测 6 台，5 台成功；其中 1 台连接异常（edge-02，已自动隔离）、1 台负载偏高（node-01）。` |
| 权限拦截（403） | `[403] viewer 无权执行 INSPECT_ALL` | 标题：`当前账号无操作权限`；正文：`只读成员（viewer）无法发起全量巡检，如需执行请切换为管理员身份。` |
| 模拟通道发送 | `[200 OK] 已送达收件箱` | 标题：`报告已投递至模拟收件箱`；正文：`最新巡检报告已写入下方发送记录（当前为本地模拟模式，未连接外部邮箱服务器）。` |
